# Gate P2 — the PowerPoint checklist

**What this is**: the fill-in form for the one thing this project cannot test itself — whether
**PowerPoint** opens a deck docsai wrote without offering to repair it. It is the acceptance
criterion of Phase 15 (`kb/61-phase-15-plan.md`) and the closing condition of risk **P2** in
[`../technical-analysis-presentations.md`](../technical-analysis-presentations.md) §7. It expands
step by step the ten-minute procedure written in
[`P3-preserved-skeleton.md`](P3-preserved-skeleton.md) §6.2, which was written before the writer
existed and names a throwaway harness that no longer does.

**Who runs it**: a human, in front of a real PowerPoint, on Windows or macOS. Nothing in this
repository can stand in for that, and this document exists precisely so that nobody is tempted to
let it. LibreOffice is not the oracle: spike P3 §2.4 measured LibreOffice opening a package with
five dangling relationships without a murmur.

**How long it takes**: about twenty minutes once the decks are built.

**Status**: *not yet run.* When it is run, fill in §3 in this file, record the outcome in
`P3-preserved-skeleton.md` §6.2 as that section asks, and — only if every deck passes — close P2
with the wording prepared in `../technical-analysis-presentations.md` §7.1.

## 1. Building the decks

The decks are **not committed**. They are derived, byte for byte, from the tracked corpus and the
tracked writer, so committing them would add a class of artefact this repository does not carry
(the only binaries in the tree are `corpus/`, generated by `corpus/generate.py` and checked by
`--check`) and would freeze in git a file whose whole purpose is to be rebuilt from the writer as
it is *today*. They are built into `target/p2-gate/`, which is gitignored, and rebuilt in one
paste.

Run from the repository root, on the commit under test:

```bash
cargo build -p docsai-cli
D=target/p2-gate; B=./target/debug/docsai
rm -rf "$D"; mkdir -p "$D"
cp corpus/pptx/charts-embedded.pptx corpus/pptx/smartart-fallback.pptx \
   corpus/pptx/raw-preserved.pptx "$D/"

# Deck A — a preserved deck, edited, written back.
"$B" convert "$D/charts-embedded.pptx" -o "$D/charts-embedded.dmk.md"
sed -i 's/^## Ventas por zona /## Ventas por zona (revisado) /' "$D/charts-embedded.dmk.md"
"$B" convert "$D/charts-embedded.dmk.md" -o "$D/A-charts-edited.pptx" --verbose

# Deck B — the objects the writer only re-injects, edited.
"$B" convert "$D/smartart-fallback.pptx" -o "$D/smartart.dmk.md"
sed -i 's/^## Proceso /## Proceso (revisado) /' "$D/smartart.dmk.md"
"$B" convert "$D/smartart.dmk.md" -o "$D/B-smartart-edited.pptx" --verbose

# Deck C — attribute-free Markdown, no preserved package at all.
cat > "$D/plain-deck.md" <<'MD'
---
docmark: "1.2"
source-format: pptx
title: "Quarterly review"
---

## Opening

## Where we are

- Revenue is up nine per cent
- Two markets opened in March
- Churn is flat

## What we do next

Hiring closes in May. The platform migration starts the week after.

## Thank you
MD
"$B" convert "$D/plain-deck.md" -o "$D/C-plain-template.pptx" --verbose

# Deck D — optional, the fourth family of preserved objects.
"$B" convert "$D/raw-preserved.pptx" -o "$D/raw.dmk.md"
sed -i 's/^## Lo que no se modela /## Lo que no se modela (revisado) /' "$D/raw.dmk.md"
"$B" convert "$D/raw.dmk.md" -o "$D/D-raw-edited.pptx" --verbose

# Deck N — the negative control. Not written by docsai: a valid package with
# three parts removed and the relationships left pointing at them, which is
# the failure P3 §2.4 measured LibreOffice accepting.
python3 - "$D" <<'PY'
import sys, zipfile
d = sys.argv[1]
drop = {"ppt/charts/chart1.xml", "ppt/charts/_rels/chart1.xml.rels",
        "ppt/embeddings/workbook1.xlsx"}
zin = zipfile.ZipFile(f"{d}/charts-embedded.pptx")
with zipfile.ZipFile(f"{d}/N-negative-control.pptx", "w", zipfile.ZIP_DEFLATED) as zout:
    for i in zin.infolist():
        if i.filename not in drop:
            zout.writestr(i, zin.read(i.filename))
PY

for f in "$D"/[ABCDN]-*.pptx; do python3 corpus/opc_check.py "$f"; done
```

The last line must print `ok` for A, B, C and D and **`FAIL` for N** — that is the control on the
control. Copy the five `.pptx` files to the machine with PowerPoint; nothing else is needed there.

### Why these three decks

The plan asks for three, and Phase 15 has exactly three paths that produce bytes:

| Deck | Path it exercises | What only PowerPoint can say about it |
|---|---|---|
| **A** `A-charts-edited.pptx` | A preserved package, one slide's title retyped, everything else copied entry by entry (15-A, 15-B, 15-F) | Whether a *spliced* package — an archive whose members are the original stored bytes except one rebuilt slide part — is still a package PowerPoint trusts. It also carries the chart and its embedded workbook, so *Edit Data* is a live check that a part the writer only copies survived the splice. This is the deck P3 §6.2 named first. |
| **B** `B-smartart-edited.pptx` | Raw re-injection (15-D): SmartArt as five `dgm:` parts behind an `mc:AlternateContent`, with the same slide retitled | The one construct where LibreOffice provably cannot stand in: LibreOffice takes the `mc:Fallback` shape, PowerPoint resolves `mc:Choice` and renders the diagram from the `dgm:` parts. If the splice broke a diagram relationship, only PowerPoint would show it. P3 §2.4 lost four of these five parts to a naive rewrite with no visible change at all. |
| **C** `C-plain-template.pptx` | The whole package generated on the embedded template from attribute-free Markdown (15-G) | **No application has ever opened this file.** Every other path re-emits bytes some real producer wrote; this one is the only package docsai authors end to end — `[Content_Types].xml`, `ppt/presentation.xml`, four slides, the layouts, the master, the theme. It is the acceptance criterion «a deck written from attribute-free Markdown opens correctly with a sensible layout», and the criterion says *opens*. |

`D-raw-edited.pptx` (a group, a custom geometry, `p:transition`, `p:timing`) is offered as a
fourth because those are the raw families deck B does not carry and no corpus deck combines them
with SmartArt; it is optional because the mechanism is the same one deck B tests. `N` is not a
docsai output at all: it is there to prove the oracle is *sensitive*, which is P3 §6.2 step 4 and
the reason a page of green ticks means anything.

**Not covered by any deck**: a real OLE embedding (`p:oleObj`). The corpus has no such fixture —
the embedded workbook behind deck A's chart is the closest thing in the tree, and it is reached as
a `package` relationship, not as a slide-level OLE shape. Recorded here rather than implied away.

## 2. What counts as a pass, and what counts as a failure

Read this before starting; it decides the answers in §3.

- **A repair dialog is a failure.** Any wording of it: «PowerPoint found a problem with content in
  …», «repair», «recover». It is a failure even if the repaired deck then looks perfect — the
  criterion is the dialog, not the pixels. Note the exact wording; it is the only diagnostic
  PowerPoint gives.
- **A deck that opens but will not save again is a failure** (P3 §6.2 step 3). PowerPoint is
  stricter on write than on read.
- **A missing object is a failure.** A chart that is now a picture, a SmartArt diagram that came
  back as its fallback text box, a shape that vanished.
- **A visual difference that is not a loss is not a failure here.** Fonts substituted because the
  machine lacks them, a slightly different line break: note them under «observations», do not fail
  the deck. That is what the render gate (`corpus/render_gate.py`) is for, and it has its own
  measured threshold.
- **The negative control failing to fail is a failure of the whole run.** If PowerPoint opens deck
  N without complaint, then PowerPoint is not the strict oracle this project assumed and every
  other tick on the page is worth less. Stop and record that; do not close P2.

## 4. After the run

1. Fill in §3 above and commit this file with the outcome.
2. Copy the verdict into `P3-preserved-skeleton.md` §6.2, which asks for it there.
3. **If and only if the verdict is «P2 CLOSES»**: replace the P2 row of
   `../technical-analysis-presentations.md` §7 with the wording prepared in §7.1 of that file,
   filling in the version and date from §3, and delete §7.1.
4. Tick the acceptance criterion «No repair dialog in PowerPoint or LibreOffice for any corpus
   output (checklist signed)» in `kb/61-phase-15-plan.md`, and note in `kb/72-phase-15-close.md`
   that the phase's last open box is closed.
5. If any deck failed, the failure is a Phase 16 input, not a Phase 15 patch: record it as a KB
   entry with the exact dialog text and the deck, so that whoever fixes it starts from evidence
   and not from a memory of a dialog.
