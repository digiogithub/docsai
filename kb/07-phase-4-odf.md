# 07 — Phase 4 ODF (ODT / ODS ⇄ DocMark)

What landed for OpenDocument support, the non-obvious decisions, and traps for
later fidelity work.

---

## Status

**Closed for the core path.** `docsai-odf` reads and writes `.odt` and `.ods`.
The convert support matrix lists both directions; goldens live under
`corpus/odt/` and `corpus/ods/`; pipeline round-trip tests cover basic ODT/ODS
idempotence of DocMark.

---

## Delivered

| Item | Where |
|---|---|
| ODF package I/O (`mimetype` first + stored, manifest, Pictures) | `docsai-odf::package` |
| Shared XML tree (`quick-xml`) | `docsai-odf::xml` |
| Automatic-style de-automatization → parent + deltas | `docsai-odf::styles` |
| ODT body/styles/meta/lists/tables/images/headers/footnotes | `docsai-odf::odt` |
| ODT writer regenerating automatic styles and graphic styles | `docsai-odf::odt::write` |
| ODS values, OpenFormula, merges, sheet images | `docsai-odf::ods` |
| ODS writer (custom, not spreadsheet-ods) | `docsai-odf::ods::write` |
| Detect Certain via package `mimetype` | `docsai-office::detect` |
| Convert routing + SUPPORT | `docsai-convert` |
| Corpus + goldens | `corpus/odt/*`, `corpus/ods/*` |

---

## Technical decisions

1. **Custom readers/writers only.** After the OOXML path proved `zip`+`quick-xml`
   sufficient, the same pattern was used for ODF. `calamine` / `spreadsheet-ods`
   were skipped to keep one I/O stack and a small binary.
2. **De-automatization is mandatory on read.** ODF puts direct formatting in
   `office:automatic-styles`. The IR wants named style + run/para deltas
   (`FontProps::minus` / para deltas), matching Docx behaviour.
3. **OpenFormula is never translated** (risk R5). Prefixes `of:` / `oooc:` are
   stripped on read; write emits `of:=…`. Dialect stays
   `FormulaDialect::OpenFormula`.
4. **Raw format tag is `odf`.** Non-odf `raw-block` fragments are dropped on write
   with `RawBlockDropped` (same idea as OOXML `ooxml`).
5. **Mimetype detection.** Reading the first package entry `mimetype` yields
   `DetectScore::Certain` for ODT/ODS so extension-less inputs still route correctly.

## Corpus

| Dir | Files | Traits |
|---|---|---|
| `corpus/odt/` | 10 | basic text/styles, lists, tables, images (inline/float/transform), headers, footnotes |
| `corpus/ods/` | 4 | value types, formulas, merges, sheet images |

Generated by `corpus/generate.py` (`write_odf_package` + per-trait builders).
Goldens: `DOCSAI_UPDATE_GOLDENS=1 cargo test -p docsai-convert --test goldens`.

---

## Cross-format notes

- docx ⇄ odt and xlsx ⇄ ods go through the IR and work for common traits.
- Dialect-specific raw blocks and some style edge cases are not portable; the
  writer must warn, never silently drop fidelity without a `ConversionReport`
  entry.

---

## Known gaps / non-blocking polish

- Full named-style catalogue fidelity beyond the traits exercised by the corpus.
- Column width / row height mapping for ODS is minimal.
- LibreOffice open checklist (no soffice in CI yet).
- Large-sheet performance budget (shared with Phase 3/8).

---

## Traps

- ODF `mimetype` **must** be the first ZIP member and **stored** (not deflated) or
  some consumers reject the package.
- Raw strings in tests that contain `#RRGGBB` need `r##"…"##` so `#"` does not
  terminate the literal.
- Sheet cell repeats (`number-columns-repeated`) can be huge; cap them when
  expanding into the IR grid.
- When writing formulas, keep the OpenFormula body without a leading `=`; add
  `of:=` only at the attribute boundary.
