# 103 — Phase 18 E: the cross conversion

Increment 18-E of [[94-phase-18-plan]], on the reader [[98-phase-18-odp-reader]], the DocMark half
[[100-phase-18-odp-docmark]] and the writer [[101-phase-18-odp-writer]]. The phase's second
acceptance criterion:

> **pptx → DocMark → odp and back work for common traits; drops are warned, never silent.**

Both directions now work, both are gated by a grammar and by a renderer, and the pairing
[[96-phase-18-corpus]] built the two corpora around is a **constant the test walks cell by cell**
rather than a paragraph in a README.

## What the increment found before it built anything

Both directions were broken, and one of the two was broken in the way this project treats as the
worst kind.

**`pptx → odp` refused, and named the wrong thing.** The `.odp` writer opened the deck's preserved
package — an OPC archive — and reported `invalid document: content.xml: required part 'content.xml'
is missing`. The message names a part the caller never had and says nothing about the dialect.

**`odp → pptx` "succeeded" and wrote an ODF package under a `.pptx` name.** An ODF package is a ZIP,
so `Package::open` succeeded; `deck_parts` then found no `ppt/presentation.xml`, `seed` returned
`Ok(None)` on the "unreadable" branch, and `reemit` copied every entry of the ODF archive into the
output. The only warning was *«the preserved package does not name its slides in a way this writer
can follow, so it was copied unchanged»* — true of a `.pptx` and useless here. Repro before the fix:

```
docsai convert corpus/odp/basic-slides.odp -o /tmp/b.dmk.md
docsai convert /tmp/b.dmk.md -o /tmp/b.pptx --verbose   # 4 KB of mimetype + content.xml
```

Both are now the **same** decision, taken in the same place in both writers and said out loud: a
preserved package of the wrong dialect is never spliced into, and the deck is written on the
writer's embedded template with a `Degraded` warning naming the dialect the package was
(`odp/write.rs::source_package`, `pptx/write.rs::skeleton_bytes`). The question is asked of the
**archive**, not of the deck's `source-format:`, because the archive is what the writer opens and a
front-matter key is only a claim about it.

## 18-D's refusal, reversed with its own argument

[[101-phase-18-odp-writer]] refused a deck with no preserved package by name, because there was no
ODF template and *«inventing a master page, a page layout and a presentation style family would be a
design nobody chose, substituted silently»*. That argument is right about the deck it was arguing
about: a deck read from a `.odp` always has its own package.

**18-E is the case it does not cover.** A deck read from a `.pptx` carries an OPC package and
therefore has no ODF package at all; there is nothing to splice into, and refusing would refuse the
conversion the plan asks for by name. So the second half of 18-D's own argument is what stands — the
substitution happens **and it is warned**, exactly as the `.pptx` writer has done since 15-G.

`crates/docsai-odf/assets/default-template.odp` is generated by `corpus/generate.py`
(`odf_default_template`) for the reason the pptx template is: every byte is reviewable source in
this repository, and `python3 corpus/generate.py --check` fails if the checked-in file stops being
what the generator produces. It carries **no `draw:page`** — a page is what the writer generates —
and the master page and the two `style:presentation-page-layout` the corpus already declares, by the
same names, so a generated deck resolves through the same cascade a fixture does.

### The generator, and why the splicer never sees a generated deck

`crates/docsai-odf/src/odp/write_gen.rs` writes an `office:presentation` from the model into the
template's `content.xml` and hands the result to the ordinary writer, so a generated page reaches
the archive through the same door a preserved one does. What it writes:

| the model's shape | the page gets |
|---|---|
| a placeholder | `draw:frame` with its `presentation:class` and a text box |
| a text box | `draw:frame` with a graphic style and a text box |
| a picture | `draw:frame` with a `draw:image`, and the bytes in `Pictures/` + the manifest |
| a table | `draw:frame` with the `table:table` the ODF block writer renders |
| speaker notes | `presentation:notes` with a notes frame |
| a chart, a group, an OLE payload, a comment | **nothing**, and a `Degraded` warning naming it |

The **splicing pass is skipped entirely** for a generated package, and that is not an optimisation:
the splicer re-reads the package and compares body against body, so over a package it has just
written it would rewrite every body a second time from a model that knows less than the first
writing did — which list style a numbered list points at, where a picture sits — and undo it. It was
measured: a crossed numbered list came back bulleted because the second writing dropped the
`text:style-name` the first had put on it.

## What "work for common traits" is asserted to mean, measured

`crates/docsai-convert/tests/cross_matrix.rs`. **Twenty-two cells**: sixteen traits both corpora
carry, the five `.pptx` traits ODF has no counterpart for, and `presentation-classes.odp`, which has
no `.pptx` mirror. The walk asserts its own size, asserts every fixture of both corpora appears in
**exactly one** cell, and asserts a cell naming a fixture on one side declares a crossing from that
side — so a fixture added tomorrow fails the build rather than quietly not being measured. That is
the shape `edit_matrix.rs` gave §11's matrix in Phase 17.

The property is stated per cell, and it is neither byte identity — two dialects, two packages — nor
a render diff, which would be measuring the template's fonts:

1. **The visible text survives, as a multiset.** Every line of text the source deck's DocMark shows
   is in the crossed deck's, with the same multiplicity, **except** the lines the cell declares lost
   — and every line the crossing loses is one the cell declares, **verbatim**. A multiset and not a
   sequence on purpose: PresentationML ranks a page's placeholders by `p:ph` and ODF has no index to
   rank by, so 18-B orders by position, and a reading order that changes is a fact about the
   dialect rather than a loss. Whole lines and not fragments, because `Ventas` is a chart's column
   header *and* half of the slide title above it — the first draft used `contains` and passed a cell
   it should have failed.
2. **The warnings cover the losses exactly, both ways round.** Every warning the conversion raises
   matches a fragment the cell declares, and every fragment the cell declares matches a warning. A
   drop with no warning fails; a warning for a loss that did not happen fails as hard.
3. **The package is real**: non-empty, and readable back by this project's own reader, which is what
   produces the DocMark rule 1 compares.

### The matrix, as it stands

Sixteen shared traits, both directions; five `.pptx`-only, one direction; one ODF-only, one
direction — **thirty-eight crossings**.

| trait | → `.odp` | → `.pptx` |
|---|---|---|
| two slides, title and body | warned (index) | **intact** |
| slide order against the part names | warned (index) | **intact** |
| a placeholder inheriting everything | warned (index) | **intact** |
| an empty placeholder is content | warned (index, placement) | warned (layout, `text`) |
| nested bullets, two kinds, three levels | warned (index, placement) | warned (layout, `text`) |
| speaker notes | warned (index) | **intact** |
| document order that is not reading order | warned (index) | warned (layout, `text`) |
| the constructs with no IR node | **cannot cross**: two shape labels | warned (layout, preserved object) |
| a table on a slide | **intact** | warned (layout) |
| a picture with explicit geometry | **intact** | warned (layout) |
| free shapes with their own geometry | warned (preserved shape) | warned (layout, preserved object) |
| an embedded chart, one series | **cannot cross**: the series table | warned (layout, chart design) |
| an embedded chart, two series | **cannot cross**: title + series table | warned (layout, chart design) |
| an embedded OLE object | warned (embedded object) | warned (layout, preserved object) |
| a commented slide | **cannot cross**: three comment bodies | **intact** |
| forty slides | warned (index) | **intact** |
| a crossed notes relationship (pptx only) | warned (index) | — |
| a cached autofit scale (pptx only) | warned (index) | — |
| a chart with a stale workbook (pptx only) | **cannot cross**: the series table | — |
| SmartArt behind `mc:AlternateContent` (pptx only) | **cannot cross**: the fallback label | — |
| a macro-enabled package (pptx only) | warned (index) | — |
| the `presentation:class` vocabulary (odp only) | — | warned (layout, `text`) |

Two asymmetries are worth reading rather than skimming.

**Nothing at all is lost on the way to `.pptx`.** Every one of the seventeen `.odp` fixtures crosses
with its whole text: the `.pptx` generator writes a text box for a stub it cannot reproduce and a
`c:chartSpace` for a chart, so a preserved shape's label and a chart's cached series both survive.
Five of them cross with **no** warning beyond the design substitution.

**Four things cannot cross into `.odp`**, and each is a fact rather than a to-do: an ODF chart is a
whole sub-document with its own numbers, which this project writes for no dialect; an OLE payload is
a stream it has never produced; an ODF annotation is markup no writer here writes ([[101-phase-18-odp-writer]]
says so about the splicing path too); and a raw fragment is markup of the dialect it was read in,
which DocMark already drops with `RawBlockDropped` in 18-C. Each is a `Degraded` warning naming the
construct **and** the dialect.

## The five defects this increment found, and what became of each

Three of the five are in code shared by both formats and were invisible until a deck was made to
cross.

1. **A `.pptx` written from a `.odp` was an ODF package renamed.** Above. Fixed:
   `crates/docsai-office/src/pptx/write.rs::skeleton_bytes` + `is_ooxml_package`/`dialect_of`.
2. **`p:ph type="text"` — invalid OOXML, silently.** 18-B put ODF's `text` class in
   `PhType::Other`, and `PhType::as_str` promises «the PresentationML keyword». Writing it out
   produced a `p:ph@type` outside ECMA-376's **closed** enumeration, which `xmllint` refuses. Found
   by the schema gate's new cross arm, on four decks. Fixed:
   `crates/docsai-office/src/pptx/write_gen.rs::pml_type` substitutes `body` — the nearest role the
   dialect names — and the substitution is a `Degraded` warning naming the construct and the
   dialect. Repro before the fix:
   `docsai convert corpus/odp/presentation-classes.odp -o /tmp/p.dmk.md && docsai convert /tmp/p.dmk.md -o /tmp/p.pptx && xmllint --schema schemas/ooxml-transitional.xsd <slide1.xml>`.
3. **A generated `.pptx` placeholder ignored the geometry the model states.** `p:spPr` was written
   empty — «wherever the layout puts it» — which is right for a deck typed by hand and wrong for a
   deck crossing from ODF: two `presentation:class` frames of one class both landed on the layout's
   single body rectangle and **drew on top of each other**, with nothing saying so. Seen in
   LibreOffice, not in a test. Fixed at `write_gen.rs`: a placeholder that states a whole rectangle
   keeps it, and an absent one still inherits.
4. **The ODF table writer lost every table's header row, silently.** ODF states «the first row is a
   header» by *wrapping* it in `table:table-header-rows` and the reader
   (`crates/docsai-odf/src/odt/body.rs:341`) decides `Table::header_row` on exactly that element;
   `crates/docsai-odf/src/odt/write.rs::write_table` wrote every row loose. A `.pptx` table crossing
   into a `.odp` came back with its header demoted to a data row and an **empty** header drawn above
   it. Fixed; it is shared with the `.odt` and `.ods` writers, whose output no golden pins, and no
   golden moved.
5. **A crossed numbered list came back bulleted.** ODF states numbering **in a list style**, never
   on the list, and a deck crossing from PresentationML carries `List::ordered` and no list
   definition at all. Fixed in `write_gen.rs`: a generated ordered list points at a
   `text:list-style` this writer declares, ten levels deep because `ListDef::is_ordered_at` is asked
   with the list's absolute nesting depth.

## The two silent losses 18-D handed over: both fixed, in one function, with no specification change

Both were `deck_writer`'s from the outside and both turned out to be **one** function's:
`docsai_model::addressing::walk::implicit_shapes`, which is the single place the serializer and the
addressing walk both ask what a slide writes without a container.

**«DocMark-P silently turns an ODF `subtitle` into a body.»** §11.2 rule 2 says *«**the layout's**
primary body placeholder is implicit»*. The code conflated two different questions: a layout the
catalogue does not hold states nothing (and the first body-like placeholder in reading order is then
the best answer there is), while a layout it *does* hold and which declares no body index has said
there is no primary body — and rule 2 then leaves nothing to be implicit.
`corpus/odp/presentation-classes.odp`'s `AL2T1` is the second case. Separating them is not a
specification change; it is the specification's own words.

**«DocMark-P silently loses an empty body placeholder.»** Rule 2 writes the implicit body's blocks
at slide level, and an empty body has none — so it reaches the file as nothing at all and comes back
as a placeholder the deck no longer has. An **empty** body is therefore not implicit, whatever the
layout says, and rule 4's ordinary container costs one line and survives.

The fix moves two `.odp` goldens and **no `.pptx` golden**, which is what says the two defects were
ODF-visible rather than ODF-caused: `presentation-classes` gains `type=subTitle` on the frame that
used to be a body, and `placeholders-empty` gains the `::: {.ph}` its third shape never had. Repros
before the fix are the ones [[101-phase-18-odp-writer]] recorded, and both now come back with the
shape count they went in with.

## A sixth finding, argued rather than fixed: DocMark-P carries no canvas size

A `.pptx` states every rectangle in EMU relative to its own `p:sldSz`, and **DocMark-P's front
matter has no key for that canvas**. So a deck written from its Markdown alone knows the EMU a shape
sits at and not the page they are relative to, and lands on the template's page — 4:3 corpus decks
onto a 16:9 template. `corpus/pptx/bullets-levels.pptx` has a placeholder at 5 200 000 EMU that
reaches 17.2 cm on a 15.75 cm page: the text is in the file, the file opens, and a person cannot see
it.

Adding a `slide-size:` key is a normative change to §11.2's front matter and is **not** made here.
What is made is the honest half: `write_gen::resize_page` writes the page from
`Presentation::slide_size` whenever the model states one (a direct IR write does), and
`warn_outside_the_page` names every shape whose rectangle falls off the page, with both rectangles
in it. It fires on exactly two of the twenty-one `.pptx` decks and the matrix declares both.

## The gates learn the crossing

**`schema_gate.py`** grew `cross_arm()`: every deck of each corpus written in the other dialect and
validated against the other grammar, with the writer's parts found by diffing against the embedded
template each was generated on — a cross conversion never splices, so the template is the honest
baseline for both halves. **469 → 691 parts validated, 0 invalid.** It is what found defect 2.

**`render_gate.py`** grew `check_cross()`: every crossed package opened by LibreOffice, drawing
exactly the number of pages the package declares, with ink on each. It deliberately does **not**
compare the crossed render against the deck it came from — the two resolve through different masters
and different default fonts, so a pixel diff would be measuring the template. **127 → 254 pages
compared, 0 failures.**

`corpus/README.md` carries both rows and the matrix's own paragraph.

## The hand demonstration

`corpus/pptx/bullets-levels.pptx` → DocMark → `.odp`, and `corpus/odp/bullets-levels.odp` → DocMark
→ `.pptx`, both opened in LibreOffice beside their source.

**`.odp` → `.pptx`.** A person sees the same slide: «Niveles de viñeta» as the title, three nested
bullet levels («Primer nivel / Segundo nivel / Tercer nivel»), «Vuelve al primero» back at the first
level, and the numbered «1. Uno / 2. Dos» in its own box lower down. The bullet glyph changes (`·`
becomes `•`) and the font is the template's, which is what the design warning says. Before defect 3
was fixed the numbered box was drawn **on top of** the bulleted one and the slide was unreadable.

**`.pptx` → `.odp`.** The title, the three levels and «Vuelve al primero» are all there and in
place. «1. Uno» sits at the very bottom edge and «2. Dos» is off the page — the canvas finding
above, and the conversion says so by name and in centimetres. That is the honest statement of this
direction: the text crosses, the *placement* is only as good as what DocMark carries about the page.

## What was refused

- **Adding `slide-size:` to DocMark-P front matter.** It is normative and belongs in a specification
  increment; the loss it causes is warned instead.
- **Comparing a crossed render against the deck it came from.** It would measure the template.
- **Byte identity, or any claim near it, for a cross conversion.** Stated as impossible, in the test
  that would otherwise be tempted to claim it.
- **Widening the residue budget, `LOOP_MAX_*` or `corpus/token-budget.md`.** None moved.
  `plain_residue.rs` reads `corpus/pptx` only and stands where 14-G left it.
- **Writing an ODF chart, an ODF annotation or an OLE payload.** Each is a `Degraded` warning naming
  the construct and its dialect, which is what the criterion asks for; half-writing one would be a
  file that looks like a success.

## Carried forward

1. **DocMark-P carries no canvas size**, so a cross conversion places shapes on the target's page
   and warns when that puts them outside it. The fix is a front-matter key and a specification
   increment.
2. **A chart, an ODF annotation and an OLE payload cannot cross into `.odp`.** Three writers this
   project does not have.
3. **`col-widths="0,0"` on a crossed table**, carried unchanged from [[100-phase-18-odp-docmark]]:
   the ODF reader does not resolve `table:table-column` widths.
4. **`draw:rotation-angle`** stays carried from [[96-phase-18-corpus]], untouched a fourth time.
5. **A page layout used under two master pages** stays carried from [[98-phase-18-odp-reader]].
