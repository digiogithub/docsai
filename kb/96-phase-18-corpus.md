# 96 — Phase 18 A: the `.odp` corpus, and the gates learning a second grammar

Increment 18-A of [[94-phase-18-plan]]. The corpus comes first because both of Phase 18's
acceptance criteria are statements about files, and a criterion with no files to measure is an
assertion. Seventeen `.odp` fixtures, generated by `corpus/generate.py`; two gates that now answer
for the format instead of ignoring it; and the two things that could not be closed, written down
here rather than left to be rediscovered.

No reader, no writer, no IR. Those are 18-B, 18-C, 18-D.

## The rule this increment exists to obey

[[93-phase-17-close]] carries thirty-nine items forward, and one of them is that **there is no
schema gate and no render gate for spreadsheets**. Nobody decided that; it happened, because
`xlsx/` and `ods/` were added at a time when the gates only knew `.pptx`, and nothing said so out
loud. The cost is not theoretical: two formats have shipped without anyone ever asking whether the
markup they carry is legal.

Adding `.odp` the same way would have made it two. So the deliverable of this increment is not
seventeen files, it is seventeen files **plus the sentence that says what is measured about them**,
in `corpus/README.md`, in a table with the blanks visible.

## What the fixtures are, and how they were chosen

One trait per file, named after the `corpus/pptx` deck it mirrors — `basic-slides.odp` beside
`basic-slides.pptx` — so that 18-E's matrix pairs the two sides by name rather than by a lookup
table somebody has to maintain. `corpus/README.md` carries the full table; what belongs here is the
reasoning at the edges.

**Five pptx traits have no `.odp`, and each absence is a fact about ODF rather than a gap.**
`notes-crossed` cannot exist: `presentation:notes` is a child of its page, not a part bound by a
relationship, so there is nothing to cross. `autofit-stale` cannot exist: ODF has
`draw:auto-grow-height` and no cached `fontScale`, so no number can go stale.
`charts-stale-workbook` cannot exist: an ODF chart keeps its numbers in a `table:table` *inside
itself*, so there is no second copy to disagree with — where a `.pptx` chart caches an embedded
workbook, which is the whole reason that deck exists. `smartart-fallback` has no counterpart because
`mc:AlternateContent` is an ECMA-376 Part 3 mechanism; ODF's answer to markup a consumer does not
know is a foreign element it ignores, which is a different shape and which `comments-slide.odp`
exercises instead. `macro-enabled` has no counterpart because ODF has no macro-enabled MIME type — a
macro lives in `Basic/` inside an ordinary `.odp`. The trait exists; the *format distinction* does
not, and no fixture carries it yet.

**One trait runs the other way.** `presentation-classes.odp` has no pptx mirror and is the most
useful file of the seventeen, because it holds the ODF side of the mapping question 18-B has to
settle. `presentation:class` names a frame's role out of a closed vocabulary; `p:ph` names a type
**and an index**. Two `outline` frames on one ODF page are indistinguishable except by document
order, while `idx="1"` and `idx="2"` are not. The fixture puts both on one page so that whichever
way 18-B bends, it bends against a file rather than against a paragraph.

## The schema gate: ODF is RELAX NG, and that turned out to be the easy part

`schema_gate.py` validated `.pptx` parts against the ECMA-376 XSDs with `xmllint --schema`. ODF is
described by a RELAX NG grammar — a different technology — and the question was whether this
machine could validate one at all. It can: `xmllint` is built with RELAX NG support, it compiles the
597 KB OpenDocument 1.3 grammar in about 70 ms, and it reports its verdicts in exactly the three
line shapes the existing stderr parser already understood. So the arm is a second invocation with
`--relaxng`, sharing one parser (`xmllint()`), and not a second gate.

The grammar is **vendored**, in `schemas/odf-1.3/`, for the reason `schemas/README.md` already
argues for the ECMA files: a validation gate whose oracle can change under it without a commit is
not a gate. Two files, because `META-INF/manifest.xml` is not written in the document grammar and
validating it against the big one reports «Did not expect element manifest there». No new
dependency: `xmllint` was already required, and 605 KB of grammar is data.

### What the arm can honestly assert, and what it cannot

This is where the arm is **weaker than the OOXML one and must not be mistaken for it**. The OOXML
arm validates what the *writer* produces, and finds those parts the only way that cannot drift — by
diffing a written package against the package it was written on. There is no `.odp` writer until
18-D. So what this arm validates is what `corpus/generate.py` produces: the fixtures themselves.

That is still a real measurement — the generator is this repository's code, and it is the code every
later increment is measured against — and it is the whole difference between a gated format and an
ungated one. It is also stated in the function's own docstring, so that nobody reads the green tick
as more than it is. When 18-D lands the writer, the arm gains the writer's output the same way the
OOXML arm has it.

### Foreign markup, and why stripping it is principled rather than convenient

ODF conformance distinguishes a *conformant* document from an *extended* one, and an extended
document may carry elements and attributes from namespaces the grammar does not define, which a
consumer ignores. `strip_foreign()` applies exactly that rule before validating. It is the ODF
counterpart of `markup_compatibility()`, which applies ECMA-376 Part 3's fallback selection before
validating a `.pptx`, and it exists for the same reason: the grammar describes the conformant
subset, so validating raw bytes reports every extension as an error.

The allowed namespace set is **derived from the vendored grammar's own declarations** rather than
listed in the script, so refreshing the schema cannot leave a stale list behind. One namespace has
to be added by hand — `http://www.w3.org/XML/1998/namespace`, which the XML specification binds and
which therefore appears in no schema's namespace map. Without it `xml:id` is read as foreign and
stripped, and every `smil:targetElement` pointing at one becomes a dangling IDREF. That is not a
hypothetical: it is how `raw-preserved.odp` went red, and it is why the line has a comment.

## The render gate: reachable, and it decided a fixture

LibreOffice reads `.odp` natively, so this gate was always going to be the reachable one. What it
can assert in 18-A is narrower than for `.pptx` — there is no round trip yet, so there is nothing to
compare against — but it is the assertion schema validation cannot make: **LibreOffice opens every
fixture, draws exactly the number of `draw:page` the fixture declares, and leaves ink on each of
them.** A `draw:page` that renders blank is a fixture that isolates nothing, and 18-E's matrix would
be measuring an empty rectangle.

It earned its place immediately. `comments-slide.odp` went through three placements, and each was
measured rather than reasoned about:

| where the comment sits | ODF 1.3 grammar | LibreOffice |
|---|---|---|
| `office:annotation` under `draw:page` | invalid — «Did not expect element annotation there» | opens the deck and **silently discards** both comments |
| `office:annotation` inside a `text:p` | valid | refuses to open the deck: «source file could not be loaded» |
| `officeooo:annotation` under `draw:page` | not in the grammar (foreign) | reads it, and writes it back unchanged |

There is no placement that is both ODF-1.3-conformant and readable by the only application on this
machine that reads `.odp`. The fixture uses the third, because a corpus that isolates a trait no
application produces isolates nothing — and the foreign-element rule above is what keeps the schema
gate honest about it rather than blind to it. 18-B's reader will have to accept the extension; the
docstring on `odp_comments_slide()` is where that is written down.

The gate found two more things before that. `charts-embedded.odp` put its `local-table` after
`</chart:chart>`, where LibreOffice draws the chart anyway and the grammar says the table belongs
*inside* `chart:chart`; and `raw-preserved.odp` pointed an animation at a shape by name rather than
by `xml:id`, which every renderer tolerates and the grammar's IDREF does not. Both are exactly the
class of error a corpus accumulates silently when nobody validates it.

## Two defects found in the existing corpus

Neither was looked for. Both fell out of pointing a real ODF grammar at ODF files for the first
time.

**`office:settings` may not be empty.** Every `.odt` fixture carried `<office:settings/>`; the
grammar requires one or more `config:config-item-set`. Fixed in `odf_settings()`, which the `.odt`
and `.odp` builders now share. Ten fixtures changed bytes; no golden moved, because nothing reads
`settings.xml`.

**`draw:rotation-angle` is not an ODF attribute, and neither is `style:rotation-angle` where the
corpus puts it.** `corpus/generate.py`'s `odt_images_transformed()` writes
`draw:rotation-angle="15"` on `style:graphic-properties`. ODF 1.3 has no such attribute there: a
shape is rotated by `draw:transform` on the shape itself, and `style:rotation-angle` exists only on
chart and table-cell properties. The reader that consumes it is
`crates/docsai-odf/src/styles.rs:187`, by local name, and `crates/docsai-odf/src/odt/write.rs:791`
writes it back the same way — so the writer emits invalid ODF too.

Correcting the fixture alone would drop `rotation=15` from
`corpus/odt/images-transformed.expected.dmk.md`, which is a golden losing coverage, not a fix. The
correct repair is reader and writer work in `crates/docsai-odf`, and it does not belong to 18-A.

**This is why `odt/` and `ods/` are not in the ODF arm.** The arm is one glob away from covering
them; switching it on today reports exactly that one failure. `corpus/README.md` says so in the
coverage table and `odf_arm()` says so in its docstring, so that the next person finds a recorded
decision rather than an unexplained exclusion.

## Carried forward

1. **`odt/`, `ods/`: ODF markup unvalidated**, blocked on the `draw:rotation-angle` defect above.
   Reader + writer + fixture + golden, in one increment, and then a one-line change here.
2. **`crates/docsai-odf` writes invalid ODF** (`odt/write.rs:791`). The `.odt` writer's output is
   not schema-validated by anything, which is how this survived to Phase 18.
3. **Spreadsheets still have no gate**, `xlsx/` or `ods/`. Untouched by this increment, and now
   visible in a table rather than only in [[93-phase-17-close]].
4. **The `.odp` schema arm validates fixtures, not writer output.** Closes in 18-D.
5. **`macro-enabled` has no ODF mirror.** A `Basic/` script inside an ordinary `.odp` is a package
   trait worth a fixture whenever a reader has an opinion about it.
6. **`.odp` renders are not compared against anything.** The round-trip comparison, on the same
   comparator and the same threshold as the pptx side, arrives with the writer in 18-D.
