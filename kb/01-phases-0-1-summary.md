# 01 — Summary of phases 0 and 1

## What you can do today

```bash
docsai convert report.docx -o report.dmk.md   # extracts assets/ next to the .md
docsai convert report.docx                      # to stdout
docsai convert report.docx --fidelity plain     # clean CommonMark for LLM/RAG
docsai convert report.docx -o out.md --json     # conversion report as JSON
docsai formats                                   # support matrix for this binary
```

A `.docx` goes in and a DocMark file comes out with:

- **Document properties** (core, app, and custom) in the front matter.
- Full **style catalog**, with `w:docDefaults` and the `basedOn` chain, without flattening.
- **Paragraphs and runs**: bold, italic, strikethrough, underline (all seven styles), color,
  highlight, font, size, sub/superscript, small caps, all caps, hyperlinks, line/page/column
  breaks, and tabs.
- **Lists** rebuilt as a tree from flat `(numId, ilvl)` pairs, with their typographic definition
  in `list-definitions`.
- **Tables** with `gridSpan` and `vMerge` resolved to `colspan`/`rowspan` and absorbed cells
  marked; `::: {.table complex=true}` container for what GFM does not allow.
- **Images** with full geometry: displayed and native size, inline or floating anchor,
  position base per axis, offsets or symbolic alignment, text wrapping and side, Z-order,
  rotation, flips, crop, border, alt text, title, internal name, and hyperlink.
  Both DrawingML and **legacy VML**.
- **Sections** split at each `sectPr`, with headers and footers by scope (default, first
  page, even).
- **Footnotes** inserted at their reference point.
- **Simple and complex fields**, preserving the original instruction.
- **Raw-blocks** with the exact bytes of every unrecognized OOXML element.

What you **cannot** do yet from this early snapshot: reverse conversion and spreadsheets
were Phase 2–3 work and are now closed (see [`06-phase-2-roundtrip-closure.md`](06-phase-2-roundtrip-closure.md)
and [`05-phase-3-spreadsheets.md`](05-phase-3-spreadsheets.md)). Still later: ODF (Phase 4),
`.doc` (Phase 5), and the MCP server (Phase 7).

## Three defects the corpus uncovered

All three were on the fidelity path, and none would have been seen without running real
documents through the pipeline:

1. **Lossy length formatting.** A Word margin of 1417 twips was written as `2.499cm`
   and re-reading it produced a different value: it would have shifted margins and images on
   every round-trip. Now the first unit that represents the length **exactly** is chosen
   (`px` → `cm` → `pt` → `emu`), and a test verifies it for each case.
2. **Empty paragraphs disappeared silently.** A blank line does not survive Markdown.
   In `full` mode they are now written as `[]{.empty}`.
3. **Hyperlink style emitted twice**, inside and outside the tag.

Additionally, the spike itself uncovered a bug in the corpus generator (`w:drawing` placed
outside a `w:r`, which is invalid OOXML) before it contaminated the goldens.

## What was left out, and why

| Element | Reason |
|---|---|
| **Anonymized real documents** (Phase 1, task 10) | Requires having real documents available. Does not block Phase 2; the synthetic corpus already covers traits one by one |
| **DrawingML text boxes** (`wps:txbx`) | Travel as raw-block. The `Block::TextBox` type exists in the IR and `::: {.textbox}` is in the spec, but emitting it without the writer that rebuilds it would advance Phase 2 work |
| **Validation in Word and LibreOffice** | Phase 2 criterion (`.docx` files are not generated yet), and there is no LibreOffice in the environment |
| **Comments and track changes** | Out of v1 scope per analysis §1.1. Revisions are taken as accepted and the count is reported |
| **`w:lvlOverride` in lists** | Not modeled in v1; a `Degraded` warning is emitted |
| **xlsx reader** | Phase 3. The corpus files already exist for then |
